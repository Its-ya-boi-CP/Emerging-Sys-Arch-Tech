# Emerging-Sys-Arch-Tech

## CS 350 Emerging Systems Architectures and Technologies

### Summarize the project and what problem it was solving.

The main project in this course involved developing a thermostat system using a Raspberry Pi and different hardware components. The goal was to create a system that could read temperature data, respond to button inputs, and use LEDs to represent different operating states such as heating, cooling, and idle. This project helped demonstrate how software can communicate with and control physical hardware.

### What did you do particularly well?

I think I did particularly well with troubleshooting and getting the different hardware and software components to work together. Throughout the course, I worked with GPIO pins, LEDs, buttons, serial communication, a temperature sensor, and state machines. When something did not work correctly, I tested different parts of the system individually to find the problem instead of assuming the entire program was wrong.

### Where could you improve?

One area I could improve is planning and checking the hardware connections before running my programs. I learned that a small wiring problem can make it seem like there is something wrong with the code. I could also improve my code by adding more comments and organizing some sections into smaller functions. This would make troubleshooting and making future changes easier.

### What tools and/or resources are you adding to your support network?

Some of the tools and resources I used during this course included Raspberry Pi documentation, Python documentation, course resources, Linux terminal commands, and troubleshooting tools such as `i2cdetect`. I also learned that testing individual hardware components before combining them into a larger project is a useful troubleshooting method that I can continue using in future projects.

### What skills from this project will be particularly transferable to other projects and/or course work?

Several skills from this project can transfer to other projects. These include Python programming, debugging, working with Linux, using GPIO, understanding state machines, and connecting software with hardware. The troubleshooting skills I developed will also be useful in software engineering because many programming problems require breaking a larger problem into smaller parts and testing each part separately.

### How did you make this project maintainable, readable, and adaptable?

I made the project easier to maintain by separating different behaviors into states and functions instead of putting everything into one large section of code. I also used descriptive names for variables and functions so that the purpose of different parts of the program could be understood more easily. The state-machine design also makes the program adaptable because additional states or hardware behaviors could be added later without completely redesigning the program.
